# 分阶段成果说明（Stage Results）

ReturnGuard 按「单案取证 → 群体洞察」两阶段交付，对应赛事「从工具到情报」的价值递进。

## 阶段 A · 单案取证（已交付，核心可用）

**目标**：把一笔退货做成「可提交平台仲裁的客观证据包」，解决卖家「说不清责任」的痛点。

| 能力 | 交付状态 | 说明 |
|------|----------|------|
| 同款一致性比对 | ✅ live 回退 / 网关开通即真 | 退回件 vs 本店主图相似度，阈值取自 `/api/config`（自标定） |
| 瑕疵识别（标签） | ✅ live 回退 / 网关开通即真 | 外包装破损、缺件、污渍、功能故障等 |
| **缺陷定位红框** | ✅ **本阶段 live 化** | 真实视觉 bbox（红框）/ 回退示意框（琥珀虚线），诚实标注 |
| Listing 承诺 OCR | ✅ live 回退 / 网关开通即真 | 提取本店承诺，做货不对板核验 |
| 文本归因卷宗 | ✅ **live 真跑通**（qwen3.7-max） | 举证卷宗 + 一致性结论，提示词已加「不裁决」边界 |
| 母语语音陈述 | ✅ **live 真跑通**（TTS） | 可直接播放给客服/仲裁方 |
| 平台举证要点 | ✅ | 按平台（Amazon/AliExpress/Temu/SHEIN）返回必备材料清单 |
| 多模型协同编排展示 | ✅ **本阶段新增** | 结果卡内链路面板，逐步显示真实/回退状态 |

**差异化**：不是「截图拼图」，而是结构化、可溯源、带红框证据与可播放陈述的举证包；且**只取证不裁决**守住合规底线。

## 阶段 B · 群体洞察（已交付，选品情报核心）

**目标**：把历史退货聚合成「选品避坑 + 品控改进」情报，对应参赛赛道「智能选品引擎」。

| 维度 | 交付状态 | 价值 |
|------|----------|------|
| 品类退货热力 | ✅ | 哪个品类最该警惕 |
| 根因归因（物流/供应商/Listing） | ✅ LLM 归因（live 真跑通） | 指向下游整改动作 |
| 供应商红黑榜 | ✅ | 选品/采购决策依据 |
| 地区 × 季节交叉 | ✅ | 提前备货与区域策略 |
| 退货成本 / 物流占比估算 | ✅ | 成本意识，非精确核算 |
| 胜诉率 KPI | ✅ 环形图 + 色温映射 | **标注为历史分布参考，非选品成功率** |

**差异化**：从「单案救火」上升到「群体避坑」——同一坑不再反复踩；所有指标如实标注口径（胜诉率/争议率代理指标），拒绝夸大。

## 复赛相较初赛的增量

1. **关键帧红框 live 化**：live 模式接入真实视觉 bbox，失败时诚实回退示意框；前端红/琥珀双色区分。
2. **多模型协同编排展示**：把六个模型能力串成可视化链路，体现「网关渐进开通即生效」的工程韧性。
3. **测试账号预置 + 双远程同步 + 交付物包**：可直接评审、可复现。

## 已知边界（评审透明）

- live 视觉三步（同款/瑕疵/红框）依赖网关开通多模态理解与公网图床（P3-17），当前回退演示；文本与语音已真实。
- 胜诉率、争议率、退货成本为**历史/代理口径**，用于趋势参考而非精确预测。
- 数据集为合成种子（~686 条，胜诉率~30%），用于演示算法与交互；真实业务数据经 real 源录入/导入。
