## 1. 产品概述

### 1.1 一句话定位
ReturnGuard 是面向跨境电商卖家的**「退货情报站」**：把每一笔退货纠纷沉淀为结构化证据，再聚合成选品避坑与品控洞察，帮助卖家**用退货数据反哺选品与供应链**，降低退货结构占比、提升举证胜诉率。

### 1.2 参赛赛道与价值主张
- **参赛赛道**：AI 市场洞察 · 智能选品引擎。
- **双阶段设计**：
  - **阶段 A · 个案举证**（数据采集管道，附属能力）：上传「退回图 + 本店主图」，自动产出同款一致性、瑕疵标签、货不对板判定、举证卷宗与母语语音。
  - **阶段 B · 群体洞察**（产品主体，赛道核心交付物）：聚合案件库，输出多维洞察看板——品类热力、根因归因、供应商红黑榜、平台胜诉对比、异常预警、选品建议。

### 1.3 解决的核心痛点
1. **只知道退、不知道为什么退**：跨境退货率高，缺乏根因分析。
2. **举证难**：调包 / 瑕疵 / 货不对板缺乏客观证据，平台仲裁时卖家常处劣势。
3. **选品盲**：退货负面信号没有反哺到选品与品控，同类问题反复发生。

## 2. 目标用户与使用场景

- **目标用户**：跨境电商卖家，尤其是多 SKU、多供应商、多平台（Amazon / Temu / TikTok Shop / 速卖通等）的中小卖家；使用角色涵盖**运营、品控、选品负责人**。
- **典型场景**：
  - 收到一笔高价值退货，1 分钟内生成举证材料提交平台仲裁。
  - 周 / 月度复盘：看哪些品类、供应商、SKU 退货集中，决定「砍品 / 换供 / 改图」。
  - 上新前核查：参考历史退货洞察，规避高风险品类与供应商。

---

## 3. 目标与非目标

### 3.1 目标（Goals）
- **G1** 单笔退货 1 分钟内产出结构化举证（相似度 / 瑕疵 / 一致性 / 卷宗 / 语音）。
- **G2** 群体洞察可下钻到**品类、平台、供应商、SKU** 四级维度。
- **G3** live 模式真实调用多模态大模型；无 Key / 网络异常时**自动回退 mock**，演示不中断。
- **G4** 部署容器化、数据落 openGauss，可公网访问。

### 3.2 非目标（明确不做）
- 不做平台仲裁的「裁决结论」——只提供客观证据，守住**「只取证不裁决」**原则。
- 不做客服 / 工单系统、不做财务对账。
- 不替代平台官方退货流程。

---

## 4. 用户故事
- 作为**运营**，我希望上传退货图就能拿到相似度与瑕疵证据，以便提交仲裁。
- 作为**品控**，我希望看到供应商质量分排行，以便决定更换供应商。
- 作为**选品负责人**，我希望看到品类退货热力与根因，以便优化上新策略。

## 5. 功能需求

### 5.1 阶段 A · 个案举证（功能①~⑤）

| 编号 | 功能 | 说明 | live 模式模型 |
|---|---|---|---|
| ① | 同款一致性比对 | 退回图 vs 本店主图，输出相似度与「是否同一件」（阈值 0.82） | `qwen/tongyi-embedding-vision-plus` 图像向量 + 余弦 |
| ② | 瑕疵视觉识别 | 识别破损 / 缺件 / 污渍 / 使用痕迹 / 功能故障等标签 | `qwen/qwen3-vl-plus` |
| ③ | Listing 承诺核验 | 提取本店图文承诺，比对退回件状态，判断货不对板 | `qwen/qwen-vl-ocr` + `qwen3-max` |
| ④ | 证据卷宗 + 母语语音 | 生成举证报告文本 + 60 字口头陈述 + 可播放语音 | `qwen3-max` + `qwen3-tts-instruct-flash` |
| ⑤ | 案件优先级排序 | 相似度低 / 缺陷重 / 金额高 → 优先处理 | `qwen3-rerank`（无额度时本地公式退化） |

### 5.2 阶段 B · 群体洞察（功能⑥）
聚合维度：
- KPI：案件数、累计退款额、胜诉率、纠纷率、结果分布。
- 品类退货热力（按退款额排序 + 高发缺陷）。
- 缺陷分布、根因分布（物流与包装 / 供应商履约 / 供应商质量 / Listing 与图文 / 非质量）。
- 供应商红黑榜（质量分 = 100×(0.5×胜诉率 + 0.5×(1−真实缺陷率))，分级：优质 / 合格 / 待改进 / 高风险）。
- 平台胜诉对比。
- SKU 纠纷明细 + 近 30 天异常预警（案件≥6 且近 30 天≥前期 1.8 倍视为集中爆发）。
- 选品 / 品控建议、洞察报告正文。

### 5.3 双模式设计
- **mock**：确定性规则 + 合成数据，免 Key，结果可复现，适合录屏演示。
- **live**：调用 Model Router 真实模型；任何异常回退 mock 并标注 `mode=mock(fallback)`，保证演示不中断。（详见《接口文档》§5）

---

## 6. 关键流程
- **单案取证**：`上传双图 → 落盘 uploads → pipeline.analyze_case → 沉淀案件库(save_case) → 返回前端`。
- **群体洞察**：`load_cases → _aggregate 多维统计 → (live) build_insights_live LLM 归因 → 返回看板`。

---

## 7. 非功能性需求
- **性能**：单案 mock < 500ms；live < 30s（受模型时延影响）。
- **可用性**：live 失败自动回退 mock；数据库**双轨**（SQLite 开发 / openGauss 部署），业务代码零改动切换。
- **部署**：Docker Compose（openGauss + FastAPI），build context 为仓库根（`..`）。
- **安全**：`MODEL_ROUTER_API_KEY`、`PUBLIC_IMAGE_BASE` 仅以环境变量注入，不入库、不进前端、不写入镜像。

---

## 8. 数据模型（案件对象）
核心字段：`case_id`、`sku`、`amount`、`category`、`supplier`、`platform`、`similarity`、`same_item`、`defect_tags`、`consistency`、`outcome`、`date`。完整定义见《接口文档》§4。

## 9. 系统集成架构
```
前端（退货情报站 index.html）
        │  HTTP /api/*
        ▼
FastAPI（demo/main.py）
   ├─ pipeline（取证 + 洞察业务逻辑）
   ├─ db（SQLAlchemy 双轨：SQLite / openGauss）
   └─ models_router ──HTTPS(OpenAI 兼容)──► 阿里云百炼 Model Router
                                          （model-router.edu-aliyun.com/v1）
```
> Model Router 集成细节（模型映射、端点、请求/响应、回退策略）见《接口文档》§5。

---

## 10. 成功度量（KPI）
- 举证**胜诉率（win_rate）**提升可见度。
- 高风险供应商 / 异常 SKU 命中准确率。
- 单案取证耗时、洞察生成耗时。

---

## 11. 风险与依赖
- 依赖赛事发放的 **Model Router Key** 与**公网图床**（live 模式；服务端回源拉图，localhost 不可达）。
- 相似度阈值 0.82 需历史样本标定，当前为经验初值。
- openGauss 容器在 Windows + WSL2 下内存敏感，已备 PostgreSQL 兜底 compose（`docker-compose.pg.yml`）。
