# 三种屏幕预演清单（P2-11）

> 用途：复赛/决赛演示前，按「桌面 / 平板 / 手机」三种屏逐条核对 ReturnGuard 界面表现，避免评委在不同设备上看到空白或错乱。
> 响应式硬约束：**desktop / TV 保持行式布局；mobile 必须纵向滚动以呈现完整信息**（不横向裁切、不空白）。

## 一、断点与布局规则

| 屏 | 断点（宽） | 布局要求 |
|---|---|---|
| 桌面 / TV | ≥ 1024px | 顶栏 + Tab 行式；看板三列网格、卡片横向铺开；评委指引浮层 fixed 顶部居中 |
| 平板 | 640–1023px | 顶栏 + Tab 行式（可换行）；看板降为两列或单列；所有卡片纵向滚动可见 |
| 手机 | < 640px | 顶栏收起为紧凑条；Tab 横向可滑动；看板单列纵向滚动；卡片不隐藏、不空白 |

## 二、通用核对项（三屏都要过）

- [ ] 顶栏品牌 + 测试账号提示可见；登录/登出可点
- [ ] 评委体验指引浮层（fixed）在登录前即显示，可关闭、刷新不重复弹
- [ ] 五个 Tab（市场洞察 / 平台举证包 / 供应商透视 / 单案取证 / 数据录入）均可点开且**内容不空白**
- [ ] 市场洞察看板 15 张卡片标题渲染正常（无 ①-⑱ 等编号残留、无中文乱码）
- [ ] 单案取证表单可提交；提交后结果区（相似度 / 瑕疵 / 红框 / 卷宗 / 语音 / 编排链路）正常出现
- [ ] 数据录入的两个卡片（批量导入 / 手动录入）可见可操作
- [ ] ROI 示例测算面板数字随输入实时变化
- [ ] 供应商透视红黑榜、平台举证包对照表正常渲染
- [ ] 明暗主题切换无对比度丢失；按钮/链接可点区域充足
- [ ] 无横向滚动条（内容超宽时由卡片内部滚动条承接，而非整页横向溢出）

## 三、分屏重点

### 桌面 / TV（行式）
- [ ] 看板三列同行铺开，首列首张默认展开；其余卡片可点展开/收起
- [ ] 评委指引浮层不遮挡顶栏与 Tab；`z-index` 正确
- [ ] 大屏下字号不过小、不拥挤；TV 投屏时关键 KPI 一眼可见

### 平板
- [ ] 看板降列后不出现「中间列空白」；卡片顺序与桌面一致
- [ ] Tab 行式换行后仍可点；无被裁切的 Tab 文字

### 手机（纵向滚动）
- [ ] **所有 Tab 内容均可纵向滚动看完**，无桌面端那种「height:100% 塌陷白屏」
- [ ] 卡片内表格 / 矩阵横向溢出时由卡片内部横向滚动承接，整页不横移
- [ ] 单案取证步骤条（上传对比图 → AI 分析 → 生成举证材料）竖向排列仍可读
- [ ] 表单输入框不被键盘/安全区遮挡；提交按钮在视口内

## 四、已知坑与回归防线

- **非 dash Tab 桌面空白**：根因是 `.content` 无显式高度时子元素 `height:100%` 塌陷。已修复（`.content{overflow:auto}` + 非 dash `.tabpane.active{display:flex;flex-direction:column;height:100%}`）。每次改布局 CSS 后，必须在桌面 + 手机各点一遍五个 Tab 确认不白屏。
- **Cloudflare 边缘缓存**：演示时若页面不更新，强制刷新（Ctrl/Cmd+Shift+R）绕过边缘缓存；已置 `Cache-Control: no-store`。
- **编号残留**：去编号后，需同时清 HTML `card-head` 与 i18n 字典 `c1_1..c3_3`（中英文），否则编号会从字典回显。
